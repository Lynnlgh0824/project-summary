# 决策记录

> **项目**: Project Summary (多项目管理系统)
> **目的**: 记录重要管理决策及其原因

---

## 决策 001: 项目边界控制

**日期**: 2026-02-25
**状态**: ✅ 已实施

**背景**:
多个独立项目需要统一管理，但要避免 AI 上下文混乱。

**决策**:
为每个项目实施严格的边界控制。

**原因**:
- **隔离性**: 防止项目间相互干扰
- **专注性**: AI 专注于单个项目
- **安全性**: 避免跨项目误操作

**影响**:
- 所有项目都有 CLAUDE.md
- Memory Scope 限制在项目目录内
- 明确的 Architecture Rules

**替代方案**:
- 共享上下文（风险高，易混乱）
- 完全独立（缺少统一管理）

## 决策 002: 统一目录结构

**日期**: 2026-02-25
**状态**: ✅ 已实施

**背景**:
各项目目录结构不一致，增加学习成本。

**决策**:
统一所有项目的目录结构。

**原因**:
- **一致性**: 降低项目切换成本
- **可预测性**: 知道在哪里找什么
- **标准化**: 便于工具自动化

**影响**:
- 统一 tests/ 结构 (tests/unit, tests/integration, tests/e2e)
- 统一 docs/ 结构 (docs/guides/)
- 删除 __tests__/ (改用 tests/)

**替代方案**:
- 保持各自结构（混乱）
- 完全统一（不现实，项目有特殊性）

## 决策 003: Memory 系统设计

**日期**: 2026-02-25
**状态**: ✅ 已实施

**背景**:
需要记录项目经验、决策和教训。

**决策**:
采用四文件 memory/ 结构。

**原因**:
- **简单**: 易于维护
- **清晰**: 职责分明
- **实用**: 覆盖核心需求

**影响**:
- memory/project-memory.md - 项目总体记忆
- memory/progress.md - 进度记录
- memory/decisions.md - 决策记录
- memory/mistakes.md - 错误教训

**替代方案**:
- 单个文件（太长，难维护）
- 复杂系统（过度设计）

## 决策 004: .env.example 分级

**日期**: 2026-02-25
**状态**: ✅ 已实施

**背景**:
项目复杂度不同，环境变量需求差异大。

**决策**:
简单项目使用简洁模板，复杂项目保持详细配置。

**原因**:
- **实用性**: 简单项目不需要大量注释
- **灵活性**: 适应不同项目需求
- **可维护性**: 减少不必要的维护

**影响**:
- project-summary, clawdbot-railway-template: 简洁版 (~17 行)
- Chiengmai, english-learning: 中等版 (~29-53 行)
- aisaasvideo: 详细版 (~131 行)

**替代方案**:
- 统一详细版（简单项目冗余）
- 统一简洁版（复杂项目信息不足）
